# Local LLM

`ai/llm/provider.py` defines a structured `InterventionContext` and provider protocol. `LocalLLMProvider` sends that evidence to a separately installed Ollama server. Configure `LLM_PROVIDER=ollama` and `LLM_MODEL_NAME=ollama:<model>` after installing and pulling a local model. Ollama remains the default provider.

Optional Gemini generation is selected with `LLM_PROVIDER=gemini`, `GEMINI_MODEL_NAME=<model>`, and a secret supplied through `GEMINI_API_KEY`. Keys are never stored in source or required for tests. If the Gemini key is missing, the configured Ollama provider remains available; when Ollama is not configured, the explicit development template remains the fallback.

When `LLM_MODEL_NAME` does not select Ollama, the system uses `DevelopmentDraftProvider`. This deterministic template is labeled “not generated by a language model”; it is a development fallback, not an LLM. The UI identifies the provider.

Risk is always produced by the trained classifier. The provider receives risk probabilities, SHAP factors, momentum, attendance, assessment, assignment engagement, retrieved sources, and available subject-mark context only to draft supportive text. Subject marks are context, not current model predictors; prompts prohibit attribution of global risk/SHAP to a subject, diagnosis, invented policy, unsupported claims, and automatic action. Faculty must review/edit and explicitly approve; approval stores the intervention and creates an in-app student notification. No external message is sent.

## Recovery AI tutor

`POST /api/v1/students/me/recovery-tutor` requires an authenticated student and accepts a question plus up to six recent user/assistant turns, not a student ID. The endpoint builds evidence only from that authenticated student's academic records and passes it to the configured Ollama or Gemini provider. Conversation history is untrusted context for follow-up questions, never academic evidence. Tutor output is structured and checked for evidence references outside that student's evidence, unsupported numeric assertions, and personalized claims in general explanations. Responses identify whether they are general explanations or based on cited student records. Unsupported questions, empty evidence, provider failures, and malformed output return explicit safe states. Tutor interactions do not write or alter grades, exams, assignments, recovery tasks, or plans; the audit entry stores the student and status, not the question, conversation, or generated text.

The student tutor deliberately does not retrieve documents. The configured local RAG index is global and has no enforceable course-level access metadata, so it cannot safely establish which indexed files a student may read. The tutor identifies this limitation and relies only on the student's authorized academic records until document-level access control is implemented.

Recovery tutoring uses the local Ollama provider by default. Academic records are not sent to an external LLM provider unless the institution explicitly sets `ALLOW_EXTERNAL_TUTOR_DATA=true` after confirming that its policy permits this disclosure. Keep it `false` to deny Gemini or other external providers for tutoring; this does not disable their use by unrelated, already-configured workflows.

To install the configured local model manually, first check available disk space and then run `ollama pull qwen3:8b`. This command is documentation only; the application does not download models automatically. Greetings have a built-in response, while general educational explanations require a working provider. If generation is unavailable or fails validation, the tutor clearly labels its deterministic guidance as not AI-generated.
